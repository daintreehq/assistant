# Test-Parity Gap Analysis — TS suite → Go suite

Read-only analysis comparing the original TypeScript test suite
(`/Users/gpriday/Projects/Daintree/assistant/tests/`, 88 `.test.ts(x)` files on
`main`) against the Go rewrite test suite
(`/Users/gpriday/Projects/Daintree/assistant-go-rewrite/`, ~52 `*_test.go` files,
323 `func Test*`). For each TS file we judge whether the *behavior* it asserts is
covered in Go and classify COVERED / PARTIAL / MISSING / N/A.

**Status legend**

- **COVERED** — a Go test asserts the same behavior(s).
- **PARTIAL** — core behavior covered, but specific assertions/edge cases are missing.
- **MISSING** — no Go equivalent; behaviors must be ported.
- **N/A** — TS machinery that does not exist in the Go/Bubble Tea rewrite
  (OpenTUI-renderer rendering, split-footer/scrollback escape mechanics, resize
  nuclear-redraw, Bun re-exec). Logic that *also* lived in those files but is real
  (state machines, data transforms) is flagged where it survives.

**How Go maps the UI.** The TS cockpit was OpenTUI/React component rendering tested via
`captureCharFrame`/`captureSpans`. The Go cockpit is Bubble Tea: pure-logic tests live
in `internal/ui` (`liveness_test.go` = transcript/turn reducer, `view_test.go` = view
widths/options, `scrollback_test.go`), `internal/ui/composer`, `internal/ui/markdown`,
`internal/ui/theme`. Component pixel-frame assertions are N/A; the *state/reducer/format*
logic underneath them is what must port.
